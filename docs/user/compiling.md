# Compiling Projects

Writing a project means working across many separate documents. **Compiling** brings them back together — pulling your work into a single, continuous output you can read, share, or export.

You can compile a project three ways:

- From the [Start Page](start-page.md), without opening the project.
- From within the project itself, once you're working in it.
- From an entity's own view, compiling just the documents associated with that entity (see below).

Before compiling you choose which documents to include and the output format — plain text, PDF, or Word (`.docx`). The text documents are stitched together in the order of your [resource tree](resource-tree.md), so they come out in the sequence you arranged them. When a draft is ready to hand off — to a reader, an editor, or just yourself for a full read-through — compiling assembles the finished whole from its parts.

## Compiling an entity's resources

Open a document you've declared as an entity (a character, location, or the like — see [Metadata](metadata.md)) and its sidebar lists every resource linked to or mentioning it. From there, **Compile this entity's resources** builds that same set — in resource-tree order — into a single output, using the same format choices as a regular compile. The resource list here is fixed to what the entity is already associated with, rather than a pick-your-own selection, and only text documents are included; any image or audio resource in the set is shown but marked as excluded. Like every compile, this only produces a downloadable file — it never changes anything in your project.
